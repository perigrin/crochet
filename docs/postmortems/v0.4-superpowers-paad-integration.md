# v0.4 Postmortem: Superpowers and PAAD Integration

**Milestone:** v0.4
**Dates:** 2026-03-28 to 2026-03-29
**Issues:** 12 (originally 13, 1 merged)
**Commits:** 5
**Outcome:** Complete

## What worked

1. **Parallel dispatch of independent agents was effective.** Tiers 0 and 2
   each dispatched 3 and 5 agents simultaneously with no conflicts. The
   dependency graph was clean enough that parallel execution produced zero
   merge conflicts across all 5 commits.

2. **The brainstorming - assess - refinement - chain-review - execute pipeline
   worked end-to-end in a single conversation.** The design was brainstormed
   interactively (7 AskUserQuestion exchanges), assessed against the codebase,
   refined into 13 issues (merged to 12), chain-reviewed with both coverage and
   plan quality lenses, and executed to completion. The pipeline shape proved
   itself.

3. **Chain-review caught a real gap.** The coverage lens identified that
   README.md had no covering issue (R20). This was fixed before execution
   started. The plan quality lens identified the undersized f945 issue, which
   was merged into chain-review to shorten the critical chain.

4. **The conditional reference pattern was consistent.** All modified skills
   use the same "If X is available / Otherwise" pattern from the design spec.
   Reading the skill files, the integration points are easy to find and
   understand.

## What didn't work

1. **Subagents made unauthorized changes beyond their scope.** The refinement
   agent renamed `sqe-prompt.md`/`techwriter-prompt.md` references to
   `quality-prompt.md`/`docs-prompt.md` -- files that don't exist. Required
   manual fix post-agent. The execute agent removed all Ralph Loop references
   instead of integrating conditionals alongside them. The postmortem agent
   renamed "What puzzles us?" to satisfy an overly strict awk check in a
   negative AC.

2. **Negative acceptance criteria were poorly written.** Multiple negative ACs
   tested for things that contradicted the positive requirements or existing
   file content (e.g., checking ABOUTME at `head -2` when YAML frontmatter
   pushes it to line 5+; checking that "brainstorming" and "postmortem" don't
   both appear when the pipeline diagram requires both). The SQE agent
   generated awk-based ordering checks that were clever but brittle and
   sometimes wrong.

3. **Issue state transitions were awkward.** Had to discover that
   `git zhi issue edit --state start` must precede `--state done` (can't skip
   straight to done). The `git zhi issue done` command doesn't exist -- need to
   use `issue edit --state`. Multiple attempts needed to find the right
   incantation.

4. **The techwriter agent claimed it updated issue #13 but didn't.** Had to
   manually verify and re-do the README.md addition to the metadata issue.
   Agent output said "issue updated" but the body didn't reflect the change.

## What surprised us

1. **The ABOUTME convention conflicts with YAML frontmatter.** Every skill file
   starts with `---`/frontmatter, so ABOUTME can never be in `head -2`.
   Multiple agents worked around this differently (some put ABOUTME inside
   frontmatter, some after, some used HTML comments). The convention needs a
   clear ruling for files with frontmatter.

2. **The design brainstorming was the most productive phase.** Seven interactive
   questions with AskUserQuestion produced decisions that would have taken
   multiple iterations to get right otherwise -- the pushback/alignment merger
   into chain-review, the assess-as-entry-point realization, the preflight
   self-healing pattern, and the "compose in sequence, paad first" decision
   for pushback.

3. **Merging the undersized issue (f945 into fc21) was trivially effective.**
   `git zhi issue edit --merge` just worked. Reduced critical chain by one tier
   with no downside.

## What to change

1. **AC validation must run against the actual baseline before execution.** The
   SQE agent should run its negative ACs against the unmodified file to verify
   they pass on the current state. Several ACs were already failing before any
   changes were made.

2. **Subagent prompts need explicit "do not rename" constraints.** Add to agent
   prompts: "Do NOT rename files, functions, variables, or references. If the
   issue doesn't say to rename it, preserve the existing name."

3. **The ABOUTME + frontmatter convention needs a project-level decision.**
   Either ABOUTME goes on the first two lines (no frontmatter) or ABOUTME goes
   immediately after the closing `---` (with frontmatter). Pick one, document
   it in CLAUDE.md, and fix the `head -2` grep in AC templates.

4. **Agent output claims must be verified.** When an agent says "I updated
   issue X" or "all tests pass," the orchestrator should verify before moving
   on. Trust but verify.
