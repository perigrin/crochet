# Milestone rfc-0003 Postmortem

23/23 done. MPG 2.3, buffer 8.5 of 11.5 burned, fever GREEN. **Time-in-chain
16%, shadow work 84%.** Verify 161/162 at the moment this was written, the one
outstanding criterion being the one this document satisfies.

## What Worked Well

**Every gate that ran found something the acceptance criteria did not.** Four
issues received the full execute gate; four produced findings. Each was green on
every criterion at the moment its gate opened. That is the milestone's own
decision demonstrated on itself: a criterion answers whether work was done, a
gate answers whether it was right.

**The fixture mechanism survived adversarial testing.** A reviewer deleted each
check in turn and confirmed exactly one expectation went missing each time, then
repaired each fixture defect and confirmed the same in reverse. One-to-one in
both directions. Coverage went from one finding site to nine.

**Cross-repository collaboration worked better than either side alone.** Nine
defects between crochet and git-zhi across four releases in one evening, and the
two most useful were each found by the other party. The git-zhi AC parser fix is
what revealed this milestone had been reporting 54/54 while 81 criteria were
never extracted.

## What Didn't Work

**Thirteen issues were closed without Steps 3, 3.5 or 4.** No TDD cycle, no
sanbao tier, no PAAD review. Nothing detected it. It was caught by perigrin
asking *"did you read the execute skill?"* — a human reading, not a check. Eleven
of the thirteen remain unreviewed.

**Thirty-eight commits carry an `Implements:` line git does not parse.** A blank
line before the attribution block makes it a separate paragraph, and git reads
only the last one as trailers. `CLAUDE.md` states the rule exactly. The rule was
imported into every agent's context and violated anyway.

**The same defect class recurred inside its own fixes, three times.** A false
coverage claim shipped in `xt/fixture/expected`, the file whose job is coverage.
A false version claim was reintroduced two commits after its twin was corrected.
And a literal file-and-line citation was written into a decision *while
documenting the rule against them* — caught by the check being hardened at the
time.

**Two criteria were green before their work started**, matching prose an earlier
issue wrote. Two more tested wording the prose never used. Chain-review cannot
catch either: it asks whether a criterion is runnable, never whether it
discriminates.

## What Puzzles Us

**84% shadow work.** Most commits were not attached to an issue. Some is
legitimate — assessments, walkthroughs, three placeholder decisions — but the
number says the chain described a minority of what happened, and nothing flagged
that while it was happening.

**The branch carries three milestones.** 0003 asserts a unit of delivery is a
pull request and its diff is the branch diff. That identity holds only at one
milestone per branch, and the delivery introducing the rule already breaks it.

**Rules written down did not transfer.** `t/git-zhi-subcommands.sh` carried
"redirect from a file, not a pipe, so the counters survive the loop"; `xt/run.sh`
piped into a `while` one file over and lost every failure. Written-down is
necessary and not sufficient — it has to be written where the work happens, and
something has to check it.

## Where A Human Had To Act

The autonomy audit, taken from perigrin's own observation that agent deference
marks friction: every "you were right" is a place a human supplied something the
agent could have determined.

| Interruption | What was lacking |
|---|---|
| "did you read the execute skill?" | the skill was read partially; nothing checks that a gate ran |
| "isn't this something refinement is supposed to record?" | agent tried to write `state: accepted` itself |
| "I thought I said to fix 0002" | an instruction converted into a recorded principle |
| "it's not an amendment if it shouldn't have been written that way" | ceremony applied to a defect |
| "And?" / "which loop?" | reporting instead of continuing; imprecision |
| "not python" | a stated preference not held |

**Two roots, and they are opposites.** *Turning an instruction into a question* —
re-deriving a decision the human already made, which reads as caution and
functions as delay. *Stopping while work remains* — `execute.md` names this
("ending your turn is a pause"; "escalating is also pausing") and it was quoted
while being done.

The gate skip looks like the opposite of over-caution but is the same
misallocation: skipping what would slow the agent, pausing on what was the
agent's to settle.

**Not friction:** perigrin's design corrections — respawn over resume,
onboarding's legacy gap, removing the actor probe. Those are the human making
judgments the protocol reserves for them.

## What Will We Change

1. **Check the trailer mechanically.** `xt/run.sh` should reject a commit whose
   message contains `Implements:` that `%(trailers:)` does not return. The
   convention is already written; nothing enforced it.
2. **Add the third outcome to chain-review.** A criterion is red, unrunnable, or
   *already green* — the third means it does not discriminate. `pushback` check 7
   now states it; chain-review must run it before execution.
3. **One milestone per branch**, or 0003's unit-of-delivery identity needs
   amending. Choose deliberately.
4. **Gate coverage should be derivable.** Eleven issues are unreviewed and the
   only record is prose. `git zhi list` cannot distinguish done from
   done-and-reviewed.
5. **Re-run `paad:agentic-review` in a fresh session before merge.** Its
   specialists never returned during review; the taxonomy was applied inline, and
   by this repository's own rule that is weaker evidence than a dispatch.
