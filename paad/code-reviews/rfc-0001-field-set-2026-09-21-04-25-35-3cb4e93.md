### [C1] The reverse README->commands check is globally disabled by an unscoped `grep`

- **File:** `xt/run.sh:227-231`
- **Bug:** The reverse direction of the README/commands cross-check is guarded by
  `grep -q "internal" "$ROOT/README.md"` — a check against the **whole README**,
  not against the name being tested. `README.md:23` contains the word "internal"
  (it is the internal-skills line). That single occurrence makes the guard true
  on every iteration, so the `note` is unreachable for every name.
- **Impact:** `docs/contributing/development-workflow.md` — a live document
  imported into every agent's context — states: *"The README and `commands/` are
  checked against each other, **in both directions**, so a skill added to one and
  not the other is caught rather than noticed."* One of those two directions
  never fires. This is the same defect class the branch exists to eliminate
  (a documented enforcement that does not happen), still live in the very
  document that was corrected for it.
- **Evidence (paired red/green control, run on a discarded copy under `/tmp`):**
  ```
  === baseline: unmodified copy ===
  (reverse check finished)

  === inject crochet:bogus into README, no commands/bogus.md ===
  (reverse check finished)              <-- genuine miss NOT reported

  === control: same copy with the word "internal" removed ===
  FAIL: README.md names crochet:bogus with no commands/bogus.md
  (reverse check finished)              <-- same miss IS reported
  ```

- **What else could have produced this:** only the global `grep`. The control run
  isolates it — nothing else about the copy changed between the two runs.
- **Suggested fix:** scope the exemption to the name under test, e.g. check that
  the README's internal-skills line names `crochet:$name`, rather than that the
  README contains the word "internal" anywhere.

### [I2] `crochet:discernment` has no failure branch for a participant that never returns

- **File:** `skills/discernment/discernment.md:81-82` (with `:233-234`, `:237-238`)
- **Bug:** The skill asserts *"Nothing tracks who failed to participate.
  Participants are dispatched, so one that does not report is a failed dispatch
  rather than a silent abstention"* — and then supplies no procedure to detect
  one, no deadline, and no instruction for what the caller does. Three other
  rules make that fatal rather than merely untidy: *"A round is a round. Collect

- **Impact:** A single non-returning participant makes the loop non-terminating:
  the drafter may not draft, may not infer a release, and the round bound never
  advances. `crochet:review` is a mandatory gate per `CLAUDE.md`, and it
  delegates its convergence to this loop, so the pipeline stalls with no
  diagnostic. A related hazard is stated but likewise unhandled at `:71-75`:

- **Evidence:** `grep -rniE "timeout|does not (report|return|answer|respond)|failed dispatch|non-respon|deadline|stall" skills/` returns only the disclaiming sentence itself. ### [I4] The declared-floor check silently passes for a `v`-prefixed or non-version string

- **File:** `xt/run.sh:253`, `:262-265`
- **Bug:** `installed` is taken as field 2 of `git zhi version`
  (`awk '{print $2}'`), guarded only against being empty. The comparison reports
  a violation only when `installed` sorts **below** `floor`. Any value that sorts
  above — including a non-version token and a `v`-prefixed real version — passes
  silently. The comment at `:259-261` reasons about a non-version **floor**
  sorting last and being reported; the same reasoning was never applied to the
  **installed** operand, where sorting last means the opposite.
- **Impact:** This check has teeth by design —
  `docs/contributing/development-workflow.md` calls the floor *"the part with
  teeth"* because preflight otherwise *"report[s] a healthy environment to an
  agent whose skills cannot work in it."* A `v0.7.1` binary is below the declared
  0.7.2 floor and passes.
- **Evidence:** floor `0.7.2`, reproducing the exact comparison:
  ```
  installed=0.7.1      lowest=0.7.1      -> REPORTS below-floor
  installed=0.7.2      lowest=0.7.2      -> SILENTLY PASSES   (correct: equal)
  installed=version    lowest=0.7.2      -> SILENTLY PASSES
  installed=abc        lowest=0.7.2      -> SILENTLY PASSES
  installed=v0.7.1     lowest=0.7.2      -> SILENTLY PASSES   <-- genuinely below floor
  ```
  `git-zhi version 0.7.2` (a plausible reshape of today's
  `git-zhi 0.7.2 (darwin/arm64)`) yields field 2 = `version`.
- **What else could have produced the green I observed on the live run:**
  installed and floor are both exactly `0.7.2` here, so the comparison has never
  had to discriminate. The check passing today is not evidence that it works.
- **Suggested fix:** validate the shape of `installed` before comparing (reject
  anything not matching `v?[0-9]+(\.[0-9]+)*`, stripping a leading `v`), and
  report an unparseable version rather than passing.
- **Confidence:** High
- **Found by:** Error Handling & Edge Cases (inline; `claude-opus-5[1m]`)
